# Генератор кликеров

Веб-приложение, которое превращает произвольную 3D-модель в **кликер**: режет её
на две половины и вырезает внутри посадочное место под механическую часть,
которая и делает щелчок. На выходе — готовые к печати STL корпуса и крышки плюс
инструкция по сборке.

Всё считается прямо в браузере: модель никуда не отправляется, сервер не нужен.

## Как это работает

1. **Загрузка.** STL, OBJ, PLY, 3MF, GLB или GLTF. Модель приводится к общей
   системе координат: центр по горизонтали, низ на нуле.
2. **Анализ.** Из сетки точек вдоль оси нажатия трассируются лучи, и все
   пересечения с поверхностью запоминаются. По ним любое горизонтальное сечение
   получается мгновенно — без повторной трассировки. Для сечения считается карта
   расстояний до контура, которая даёт две вещи: **куда** поставить механизм
   (самая «толстая» точка сечения) и **влезет ли он вообще**.
3. **Рез.** Модель делится плоскостью на корпус и крышку булевыми операциями.
   Положение реза подбирается автоматически: берётся самое низкое сечение, в
   котором механизм помещается со стенкой и под которым хватает материала на
   карман.
4. **Механика.** В корпусе вырезается карман под механизм, в крышке — канал
   толкателя, при необходимости — боковой канал для проводов.
5. **Соединение.** Вокруг механизма расставляются штифты совмещения (на корпусе)
   и ответные отверстия (в крышке), опционально — карманы под магниты. Радиус для
   каждого штифта подбирается отдельно: у прямоугольного кармана сбоку места
   меньше, чем с торца. Если запрошенное количество не влезает, ставится столько,
   сколько помещается, и об этом сообщается.
6. **Экспорт.** STL по отдельности или архив со всеми деталями и файлом
   `СБОРКА.md`. Для печати детали разворачиваются плоскостью реза на стол — в 3D
   при этом модель остаётся собранной, чтобы можно было осмотреть стык.

## Механизмы

Приложение не печатает сам щёлкающий элемент — он берётся готовым. В библиотеке
есть посадочные размеры под:

| Механизм | Карман, мм | Щелчок |
| --- | --- | --- |
| Пластина дрессировочного кликера | 22 × 14 × 5 | громкий, «настоящий» |
| Металлический купол ⌀12 (snap dome) | ⌀13 × 3 | тихий, чёткий |
| Кнопочный узел шариковой ручки | ⌀10,5 × 22 | с фиксацией в двух положениях |
| Тактовая кнопка 12 × 12 | 12,6 × 12,6 × 8 | средний |
| Тактовая кнопка 6 × 6 | 6,6 × 6,6 × 5,5 | негромкий |
| Микропереключатель мыши (D2FC / Kailh) | 13,4 × 6,6 × 7 | громкий, большой ресурс |

Плюс режим **«Свои размеры»** — задаются габариты кармана, диаметр и ход
толкателя. Размеры в таблице типовые: свою железку стоит проверить
штангенциркулем.

## Настройки

- **Масштаб** и кнопка «Подогнать под механизм» — если модель мелкая, приложение
  посчитает, во сколько раз её увеличить.
- **Ось нажатия** X / Y / Z и положение реза ползунком; под ползунком видно,
  что помещается в текущее сечение и что требуется механизму.
- **Зазор** вокруг механизма и **толщина дна** под карманом.
- **Сдвиг механизма** по осям сечения, если автоматический центр не устраивает.
- **Штифты**: количество, диаметр, высота, посадочный зазор.
- **Магниты**: карманы в обеих половинах.
- **Канал толкателя**: глухой (давим на всю крышку), сквозной (торчит кнопка,
  её можно напечатать отдельной деталью) или без канала.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
```

```bash
npm run build    # сборка в dist/
npm run preview  # просмотр сборки
npm test         # проверка геометрического конвейера
```

## Тесты

`npm test` собирает ядро для Node и прогоняет конвейер на наборе моделей — шар,
капсула, коробка, тор и заведомо слишком мелкая деталь. Проверяются не только
размеры файлов: готовые детали перетрассируются заново, и проверяется, что
карман действительно полый, дно под ним осталось, штифты торчат над плоскостью
реза, а в крышке под каждым из них есть отверстие с материалом вокруг. Отдельно
проверяется, что модели, в которые механизм не влезает, не роняют генератор, а
дают понятное предупреждение.

## Стек

TypeScript, [three.js](https://threejs.org),
[three-bvh-csg](https://github.com/gkjohnson/three-bvh-csg) для булевых операций,
[three-mesh-bvh](https://github.com/gkjohnson/three-mesh-bvh) для быстрой
трассировки, Vite.

## Ограничения

- Модель должна быть замкнутой. Дырявая сетка ломает определение «внутри /
  снаружи» по чётности пересечений, и рез получится неверным.
- Тяжёлые сетки (сотни тысяч полигонов) считаются заметное время — перед
  загрузкой их лучше упростить.
- Стенка вокруг кармана не наращивается: если в модели в этом месте тонко,
  приложение об этом предупредит, но само материал не добавит — нужно увеличить
  масштаб или сдвинуть рез.
